おむかえナビ：投稿・編集の審査制への変更

【変更内容】
・一般ユーザーは学校・送迎ポイント・見取図を閲覧できます。
・一般ユーザーの送迎ポイント新規投稿、本人の投稿編集／削除、マッピング、見取図スタンプ、校門写真・見取図画像の変更は「申請」として保存されます。
・申請中の内容は公開中データに反映されません。
・管理者は管理ページの「投稿・編集審査」で申請を確認し、承認または却下できます。
・承認時に公開データへ反映されます。
・一般ユーザーは他人の送迎ポイント編集画面を開けません。
・Firestoreルールでも一般ユーザーによる公開データの直接変更を禁止しています。
・新規登録アカウントは status=pending となり、管理者が「利用開始」するまで閲覧できません。
・既存の active ユーザーと admin 権限は維持されます。

【公開サイトの更新】
1. 現在のサイト一式をバックアップしてください。
2. このZIP内の index.html / admin.html / core.js / editor.js / schools.js / theme.css / firebase-config.js を、現在のホスティング先の同名ファイルと置き換えてください。
3. firebase-config.js は既存プロジェクトの設定をそのまま使用してください（ZIPにも元ファイルを含めています）。

【Firestoreルールの反映：必須】
1. Firebase Console を開き、対象プロジェクトを選択します。
2. Firestore Database → ルール を開きます。
3. ZIP内の firestore.rules の内容を全てコピーして貼り付けます。
4. 公開 を押します。

※コードだけ更新してFirestoreルールを更新しないと、一般ユーザーの直接編集が引き続き許可される可能性があります。必ずルールも反映してください。
※ルールだけ先に更新すると、旧版アプリの新規登録処理と整合しない場合があります。サイトファイルを更新した直後にルールを反映してください。

【動作確認】
・管理者アカウントでログインし、管理ページに「投稿・編集審査」が表示されること。
・一般ユーザーで新規投稿／本人の投稿編集／見取図の位置変更／スタンプ配置を行い、申請が作成されること。
・申請中は一般ユーザー側の公開情報が変わらないこと。
・管理者が承認すると公開情報へ反映されること。
・却下すると公開情報が変わらないこと。
・一般ユーザーが他人の投稿の編集URLを直接開いても、Firestoreルールにより保存できないこと。

【重要】
・最初の管理者アカウントは既存の管理者を維持してください。管理者が一人もいない状態で新規登録すると、利用開始や申請承認ができません。
・このZIP作成時点ではFirebase本番環境への接続・デプロイは行っていません。Firestoreルールの公開とサイトファイルの差し替えは、Firebase／ホスティングの管理画面で実施してください。
